# Dev tracker (UAT · later bugs/releases) — rules (owner, 3 Nov 2569)

- One app = one `dev_projects` row (`slug` = repo folder name; Claude's CLI runs from that repo and uses `basename(cwd)` as the default project). Users = amgo users. Admins see every project; others only projects they are a member of (`dev_project_members.role` manager/tester/viewer). Menu "Dev Management" shows when `my_profile().has_dev_access` (admin or any membership).
- Permissions live in DB (migration `20261103100000_dev_tracker`): `dev_can_view/test/manage(project_id)`. Testers may only change `sort_order` on a case (guard trigger); a result insert sets the case status (`dev_uat_result_apply`, bypasses the guard via `set_config('dev.apply_result')`). The bot API uses the service role and repeats the manager check in `botDev.ts`.
- Case numbers (`no`) are global, `generated by default as identity` — never reuse or renumber; moved aoocommerce cases keep UAT-0001…0088, new ones continue from the sequence (`dev_bump_uat_sequence`).
- Results are history: no update/delete policy. A result needs 1–8 pictures (bucket `dev-shots`, path `<case id>/…`, resized to 1600 JPEG in the browser, uploaded one by one) and a note when failed/blocked. A closed case takes no results.
- Board columns = what the tester must do first (รอเทส · ไม่ผ่าน · ติดขัด · ผ่าน · ปิดแล้ว); dropping on a result column opens the result form with that result preselected; รอเทส/ปิดแล้ว are manager-only drops (send back = round + 1 with fix note). Board reuses `.aoo-kanban` + `.aoo-task-card` (`.aoo-kanban--5` for 5 columns) and the dnd-kit sensors of `TaskBoard`.
- Failed/blocked results notify the project's managers by push (`/api/dev/notify`, server reads the result itself — the browser sends only `caseId`). Owner wants notifications to him; he is manager of every project he creates (creator trigger).
- Membership is data, not code: as of 2026-11-04 ไกด์ (ศุภฤกษ์) is `manager` in every project (owner wants him to add/edit cases everywhere but not create projects — `dev_projects_insert` is admin-only). A new project gets only its creator; add ไกด์ by hand.
- Bugs + releases are NOT built yet (owner: UAT first). Bug numbers will be per project (BUG-0001 per app) with cross-links later.
- `scripts/dev.mjs` is the CLI every project's `/uat` and `/memo` skill calls (cutover done 3 Nov 2569; old `aoo-uat` tables are retired by the aoocommerce chat). Keep the command set of the old `aoo-uat/scripts/uat.mjs` (summary · list · add · retest · close · shots) — the skills depend on it.
- MCP server `POST /api/mcp/dev` (`app/api/mcp/dev/route.ts` + `lib/mcp/devTools.ts`, 3 Nov): stateless JSON-RPC copied from aoocommerce `/api/mcp`; auth = `authBotApi` (scope dev/superadmin, general → 403) and the dev-key path guard in `botApi.ts` allows `/api/bot/dev` + `/api/mcp/dev`. Tools wrap the same `botDev.ts` helpers as the REST routes — add a feature in `botDev.ts` once, then expose it in both. Registered for the owner at user scope as `amgo-dev`; `~/.claude/skills/uat/SKILL.md` calls the tools, `scripts/dev.mjs` is the fallback. Write tools must reject unknown input fields (bug 3 Nov).
- Step reference pictures (9 Nov 2569, asked by the aoocommerce tester agent): `steps[].image` = path in `dev-shots`. Upload first (`uat_upload_image` · `POST /api/bot/dev/images` · CLI `upload`) → `<project id>/<uuid>.<ext>`; saving a case moves it to `<case id>/steps/<uuid>.<ext>` so the existing read policy (first folder = case id) covers the board without a migration. `checkStepImages` before insert/update, `attachStepImages` after. The web form only keeps pictures (devService must not drop `image`). Unattached uploads stay under the project folder unread.
