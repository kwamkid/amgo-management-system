# Expenses — reimburse + supplier payments (owner, 3 Nov 2026)

- Two kinds in one table `expense_claims.kind`: `reimburse` (staff paid first, attach receipt/own transfer slip) · `supplier` (company transfers to the supplier, attach bill/invoice — mandatory, no "no receipt" option, always `payout='transfer'`, payee bank fields required; DB constraint `expense_claims_supplier_fields`). **One approval, by finance** (owner 3 Nov: managers don't approve; the owner's "approve" is in the SCB app after the file is uploaded). New claims start at `pending_finance` (migration 20261103160000); `pending_manager`/`expense_manager_decide` are legacy only.
- Transfer stages (owner 3 Nov): finance approves → **รอส่งไฟล์ธนาคาร** (approved+transfer, `exported_at` null: pick company tile → filter person → tick → export SCB file; 1 file = 1 company) → **รอโอน (ส่งไฟล์แล้ว)** (`exported_at` set; owner approves in the SCB app) → finance ticks, attaches ONE slip, "โอนแล้ว" (slip copied into each owner's folder `<userId>/slips/`). "ย้ายกลับไปรอส่งไฟล์" clears `exported_at`. `ExpenseStatusPill` shows these stages (needs `payout` + `exportedAt`). Row text: "จ่ายจาก <company>" · how it's paid · "บัญชีปลายทาง" (owner found "โอนให้ supplier / โอนเข้า" confusing).
- **SCB file = CPX Toolkit 1.1.2 upload .txt** (owner's template `file_template/CPX_Toolkit_Template-SCB.08.69.xls`; format reverse-engineered from its VBA, see header of `lib/services/bankTransferFile.ts`): UTF-8 no BOM, `|`-separated, CRLF, HEADER/BCHDET/TXNDET×n/TRAILR, TXNDET = 28 fields, branch `0111`, fee `BEN`, product chosen automatically by payee bank — no dropdown (owner confused, 27 Nov): SCB payee → `3PT` (OAT = company's own accounts only), other bank → `RFT`. SCB destinations use the SCB check digit (`isScbAccount`); other banks go to an ORFT file (see below). Names/remarks stripped of the toolkit's forbidden chars (`scbText`). Remark [27] = who claimed what (owner 27 Nov, `remarkOf`): `<userName>: <desc>`, same person merged `a / b`, several people `, `-separated, ≤200. One file per company. Debit account = dropdown `DebitAccountPicker` over `company_bank_accounts` (many accounts/banks per company, add via `add_company_bank_account()` finance-only, migration 20261127100000, owner 27 Nov "prepare for other banks"); only SCB accounts selectable — other banks listed disabled until their file format exists. `companies.scb_debit_account` = last-used SCB account (staff form/detail show it), still set by `set_company_scb_debit_account()` on export. Before the migration runs the picker falls back to the old text input. Golden-file test in scripts/test-expense-rules.mjs. `file_template/` holds real account numbers/emails — never commit it.
- Month-end report (button "สรุปสิ้นเดือน", owner 27 Nov — the old "EXPENSES REIMBURSEMENT" form is dropped): one .xlsx with sheets "สรุปตามรหัสบัญชี" (code · name · count · total · VAT · ex-VAT, sorted by code, no code = "ยังไม่ระบุ", grand total), "สรุปตามหมวดย่อย" (stats by sub-category) and "รายการ" (every claim with sub + code + name + company). Month = `expense_date`; statuses approved+paid. `buildMonthlyReport()` in `lib/services/expenseExport.ts`.
- `vat_amount` is VAT included in `amount`; independent of category — toggle "มีใบกำกับภาษี (VAT 7%)" on the form/edit modal computes 7/107 (edit modal keeps the VAT amount editable). Company filter: `company_id` null = owner's home company (resolved in `toNamedClaim`).
- **Two-level category** (owner 27 Nov, migration 20261127120000): staff pick a main = accounting account (`ACCOUNT_GROUPS` in `lib/services/expenseRules.ts`, 12 mains, e.g. 5200-09 travel with subs taxi/toll/gas; "อื่น ๆ" has no code) then a sub-category for stats (14 keys, sub row shown only when the main has >1 sub — add subs by editing `ACCOUNT_GROUPS`). Stored: `category` = sub key (`FormSection` is an alias of `ExpenseCategory`), `account_code` = main code (null = not yet coded; `accountOf()` falls back to the sub's default `SECTION_ACCOUNT`). Finance overrides the code from the full chart `ACCOUNT_CODES` in `ClaimEditModal` (picking one of the 12 codes syncs the main tiles; other codes show main "อื่น ๆ" and keep the sub). Approving without a code is allowed; `ClaimDetailModal` warns "ยังไม่ระบุรหัสบัญชี". Legacy values travel/parking/fuel/meal are mapped by `formSectionOf()`. Not sure → typing the description auto-picks the sub via `suggestSection()`: own approved/paid claims with similar text (bigram ≥0.6) win, else keyword rules `guessSection()` built from the 1,218 historical rows of Reimbursement.xlsx (90% accurate; rule order matters — fuel before "ขนของ", Lalamove/ค่าส่ง = shipping; new 27 Nov rules for promo/packaging/stationery come after entertain so "ข้าวกล่อง" stays entertain, welfare/repair/ads before it).
- Finance edits category/account code/details before approving or paying via `ClaimEditModal` → `updateClaimDetails()` (amount only while pending_finance; changing payee/amount clears `exported_at`).
- UI (owner 3 Nov): everything expense-related lives under ONE sidebar menu "เบิกค่าใช้จ่าย" (ใบเบิกของฉัน · อนุมัติ / โอนจ่าย) — not under "รออนุมัติ" (owner couldn't find it there). Form picks the company first (shows the debit account), uses `ChoiceTiles` with icons from `components/expenses/expenseVisuals.ts`; the manage page's stage tabs are `StatusTabs` with counts from `countPending()`; companies in รอส่งไฟล์ are `StatusTabs` too.
- **No more "รวมกับเงินเดือน"** (owner 3 Nov): reimbursements are always transferred (`createClaim` forces `payout='transfer'`; finance approval no longer chooses). Payroll-linked code (payrollService, `payroll_month`) stays for legacy rows only. Row shows the money flow: "โอนจาก <company> (SCB •••xxxx) → เข้าบัญชีพนักงาน/ร้าน <bank acc · name>".
- Finance can tick many claims in every stage: bulk approve (รออนุมัติ), export (รอส่งไฟล์), mark paid (รอโอน). Receipt/slip thumbnails open the shared `Lightbox` (components/aoo, ported from aoosocial; `UatCaseModal` still has its own inline copy — switch it when that file is free).
- Manage list = column rows (รายการ · จ่ายให้ [bank logo + payee, owner 27 Nov] · หมวด · บริษัท · วันที่ · ยอด ฿ · สถานะ), rows span the card edge (`-mx-5`/`px-5`) so hover fills the row; bulk ไม่อนุมัติที่เลือก beside อนุมัติที่เลือก (one reason for all); PDFs preview in an iframe in `ReceiptGallery`; no VAT/category text in the row (icon shows the category). Row click → `ClaimDetailModal`: left = `ReceiptGallery` (big image, thumbnails, Lightbox), right = details + timeline; approve/reject/edit/mark-paid live there.
- Category tiles (`ExpenseSectionField`): main row "หมวดบัญชี" + sub row "หมวดย่อย (ไว้ดูสถิติ)", horizontal-scroll `ChoiceTiles`; sub filter ordered by `SECTION_BY_POPULARITY`. Manage rows show the first receipt image (`ClaimThumb` + `useFirstReceiptUrls`, one signed-URL request per list; count badge when >1 file). Up to 10 files per claim; finance can remove/add files in `ClaimEditModal` (`updateClaimDetails` keepPaths/newFiles — removed files stay in storage).
- Manage list filters = shared `FilterBar` + `FilterSelect` (search · person · company · หมวดบัญชี · หมวดย่อย), apply to every stage; in รอส่งไฟล์ the company comes from the logo tiles instead. Row: description bold first line, requester name below (click = person filter), category column = main short label (+ sub in small text when the main has >1 sub).
- Person filter is cleared automatically when that person has no claim in the open stage (bug 3 Nov: the select showed "ทุกคน" while still filtering, list looked empty).
- Every SCB export also stores the exact .txt in bucket `expense-receipts` at `exports/<companyId|none>/<stamp>_<lines>_<totalCents>.txt` (`saveExportFile`); "ไฟล์ที่ส่งออกแล้ว" (รอส่งไฟล์/รอโอน tabs) lists and re-downloads them as `SCB_file_reference_<stamp>.txt` (owner 4 Nov). Files exported before this have no copy.
- Out of scope (owner 4 Nov): withholding tax (หัก ณ ที่จ่าย 3%) is not amgo's job — it belongs in aoo. Other-bank payees (27 Nov): same SCB CPX toolkit, product **Other Bank Transfer (ORFT) = `RFT`** — one file per product, so an export with SCB + other-bank claims downloads 2 files (`splitByProduct`: SCB → 3PT, others → RFT). RFT row = OAT row except [5] branch `0000`; bank code = 3-digit clearing (toolkit TBBankBNT1 = our constants/banks); no SCB check digit (10–15 digits); ≤ 2,000,000 per line. Verified against accounting's `~/Downloads/CPX_Toolkit_Template-เพิ่ม-07-08.69.xls` (real accounts — the test uses made-up data; never commit real payee accounts).
- Notifications (owner 4 Nov): the SCB file sends no SMS/email to payees. Only Discord, @mentioning the claimant, on **โอนคืนแล้ว** (markTransferred) and **ไม่อนุมัติ** (financeDecide reject) — `notifyResult()` → `POST /api/expenses/notify` (server checks `is_finance`, reads claims itself, only status-matching claims changed < 10 min ago, one message per claimant, `allowed_mentions` = that user only). Channel = Discord setting `webhooks.expense`, empty → `webhooks.leave`; toggle `notifications.expense`.
