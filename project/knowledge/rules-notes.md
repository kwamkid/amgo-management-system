## 2026-08-15 — AOO Website / คิวงาน WordPress

21. **cron ทุกตัวบน cron-job.org ตั้ง method เป็น `GET` เสมอ** — POST ของ `/api/web/jobs/next` และ `/api/web/uptime` สงวนไว้ให้ปุ่มบนหน้าเว็บที่ต้องมี session (เคยเสียเวลาไล่ header อยู่ครึ่งวัน ดู bugs.md)
22. **ห้ามให้ระบบลบ/แก้ไฟล์ที่สแกนเจอเองอัตโนมัติ** — ตัวสแกนเป็น pattern matching ที่ให้ false positive จริง (วันเดียวเจอ 2 ชุด: ไฟล์แกน WP กับ Monolog ของปลั๊กอิน Google) และมัลแวร์ WordPress ส่วนใหญ่**แทรกอยู่ในไฟล์ที่ถูกต้อง** — "ลบไฟล์ที่เจอ" = ลบเว็บทิ้ง · โฟลว์ที่ตกลงกัน: สแกนเก็บหลักฐาน → คนหรือ AI ตัดสิน → **สำรองไฟล์นั้นก่อน** → ค่อยแก้ทีละไฟล์
23. **dispatcher ของตัวรันงานห้ามมีสาขา else** — ต้อง match ชนิดงานให้ครบแล้ว `throw` · เคยเขียน "ถ้าไม่ใช่ 3 อย่างแรก = backup" แล้วเกือบสำรองทั้งฟลีตตอนเพิ่มชนิดงานใหม่ลง DB ก่อน deploy
24. **คิวที่มีกติกา "ทีละงานต่อโฮสต์" ต้องมีตัวกวาดงานผี** — Vercel ตัดฟังก์ชันที่ 60 วิ โค้ดปิดงานไม่ได้ทำงาน แถวค้าง `running` = ล็อกโฮสต์นั้นถาวร (เกิดจริง คิวตาย 30 นาที)
25. **งานที่ SSH เข้าเครื่องลูกค้าต้องมีงบเวลาและทำทีละหน่วย** — ห้าม `--all` รวดเดียว · หมดเวลาแล้วต่อคิวใบใหม่ ไม่ใช่ล้มทั้งใบ

## 2026-08-15 — ความปลอดภัยตอน commit

26. **ดู `git status` ทันทีก่อน `git add -A` เสมอ** — ไม่ใช่ดูตอนเริ่มบทสนทนา · เครื่องมืออื่น (ChatGPT desktop สร้าง `.codex/config.toml` ที่มี Supabase PAT) เขียนไฟล์เข้าโฟลเดอร์โปรเจกต์ระหว่างที่เราคุยกันอยู่ได้ · ถ้าเจอไฟล์ใหม่ที่ไม่ได้ตั้งใจแก้ ให้ทักเจ้าของก่อน stage
27. **ก่อนแนะนำให้ revoke/ลบความลับใด ๆ ต้องพิสูจน์ซ้ำด้วยวิธีที่สอง** — เทียบ hash คนละวิธี (shell `sed|shasum` ติด `\n` ท้าย vs `hashlib` ที่ไม่ติด) แล้วเกือบแนะนำให้ revoke token ที่ระบบใช้อยู่จริง

## 2026-08-15 — UI ของหน้าสั่งงาน (เจ้าของทักซ้ำหลายรอบ)

28. **ปุ่มที่ทำงานกับหลายรายการ ห้าม disable เพราะบางรายการกำลังทำอยู่** — ให้กดได้แล้วไปทำ "ส่วนที่เหลือ" · การกันซ้ำเป็นหน้าที่ของเซิร์ฟเวอร์ (กรอง queued/running + cooldown) ไม่ใช่การล็อกปุ่ม · disable ได้เฉพาะตอนคำขอกำลังส่งจริง
29. **ทุกครั้งที่ระบบ "ไม่ทำอะไร" ต้องบอกเหตุผลครบทุกข้อ** — ไม่ใช่เลือกมาบรรทัดเดียวและไม่ใช่เงียบ · เช่น "ไม่มีเว็บที่ต้องทำเพิ่ม — 2 เว็บมีงานค้างคิว · 6 เว็บเพิ่งทำไปไม่ถึง 10 นาที · 17 เว็บปลั๊กอินครบแล้ว"
30. **ป้ายสถานะที่บอกว่ามีปัญหา ต้องกดเข้าไปดูรายละเอียดได้** — ป้าย "ต้องสงสัย" ที่กดไม่ได้คือทางตัน · กดแล้วต้องเห็นว่าไฟล์ไหน บรรทัดไหน แก้ไขเมื่อไหร่
31. **ข้อมูลเวลาที่ทำให้ตัวเลข "เชื่อได้" ต้องเห็นด้วยตา ไม่ใช่ซ่อนใน tooltip** — คอลัมน์สถานะ/สแกน แสดงเวลาเช็คล่าสุดเป็นบรรทัดที่สอง · ตัวเลขที่ไม่รู้ว่าของเมื่อไหร่ ใช้ตัดสินใจไม่ได้
32. **สรุปงานเข้า Discord ต้องบอกชื่อเว็บเสมอ** — ใบเดียวขึ้นชื่อเว็บนั้น · หลายใบแยกช่อง "สำเร็จ N เว็บ" + รายชื่อ และ "❌ ล้มเหลว N เว็บ" + รายชื่อ (เกิน 20 ชื่อตัดเป็น "…และอีก N เว็บ") — สรุปที่มีแต่ตัวเลขไม่บอกว่าไปยุ่งกับเว็บของใคร

## 2026-08-16 — งบเวลา · การอ้างสถานะ

33. **ก่อนบอกเจ้าของว่า "ยังทำไม่ได้เพราะ X" ต้องตรวจ X ของจริงก่อน** — เอกสาร `docs/cron.md` เขียนค้างว่า `NEXT_PUBLIC_APP_URL` ยังเป็น ngrok ผมยกมาพูดซ้ำหลายรอบโดยไม่ตรวจ ทั้งที่โดเมนจริงตั้งมาตั้งแต่ 9 ส.ค. · เอกสารคือสิ่งที่เคยจริง ไม่ใช่สิ่งที่จริงตอนนี้ — ยิง `curl` / ถาม DB ก่อนเสมอ
34. **ค่าคงที่เรื่องเวลาที่ต้อง "บวกกันแล้วไม่เกินเพดาน" ต้องมีเทสต์ผูกไว้** — ห้ามกระจายอยู่ในไฟล์ที่ใช้งาน · รวมไว้ที่เดียว ([jobBudget.ts](/lib/services/web/jobBudget.ts)) แล้วเขียนเทสต์ที่ตกทันทีเมื่อผลรวมเกิน ([test-job-budget.mjs](/scripts/test-job-budget.mjs)) · เทสต์ต้องมีข้อพิสูจน์ด้วยว่ามันจับของจริงได้ (ยัดสูตรเดิมเข้าไปแล้วต้องตก)
35. **งานที่ถูกตัดเพราะ "เราให้เวลาไม่พอ" ห้ามนับเป็นความผิดของสิ่งที่ถูกตัด** — ปลั๊กอินที่โดนตัดกลางคันเพราะรอบนั้นเหลือเวลาน้อย ถ้าไปเพิ่มตัวนับพลาด สุดท้ายระบบจะเลิกลองของที่ยังอัปเดตได้เพราะดวงซวย · แต่ตัวที่**ได้เวลาเต็มเพดานแล้วยังไม่จบ ต้องนับพลาดตามปกติ** ไม่งั้นมันจะถูกลองใหม่ทุกคืนตลอดกาลโดยไม่มีใครรู้
36. **เขียว ≠ ปลอดภัย เมื่อแหล่งข้อมูลเดียวคือตัวที่เราเฝ้าอยู่** — ปลั๊กอินเสียเงินที่ license หมดจะไม่รายงานว่ามีอัปเดต ระบบจึงขึ้น "ครบแล้ว" ทั้งที่มีช่องโหว่ · อะไรที่ต้องมี license ต้องมีแหล่งเทียบจากข้างนอก

## 2026-08-22 — งวดเงินเดือน · การแก้ข้อมูลย้อนหลัง · จังหวะที่ถามผู้ใช้

38. **ย้อนแก้ข้อมูลที่กลายเป็นเงิน ทำได้เฉพาะขาลด ห้ามแจกเพิ่ม** — สคริปต์แก้ย้อนหลังต้องข้ามแถวที่แก้แล้วตัวเลข "เพิ่ม" เสมอ (ตอนล้างใบลืมเช็คเอาท์ ข้ามไป 2 ใบที่จะทำให้ 0 → 8 ชม.) · ถ้าจะเพิ่มให้ใคร ต้องเป็นการตัดสินใจของเจ้าของ ไม่ใช่ผลข้างเคียงของสคริปต์
39. **ก่อนลบ/ทับแถวไหน ต้องดู `updated_by` + เนื้อหาที่พิมพ์มือก่อนเสมอ** — ตัวเลขที่ระบบเติมผิดไม่ได้แปลว่าทั้งแถวเป็นขยะ · และถ้าเจ้าของอนุมัติบนข้อมูลที่เราสรุปผิด ต้องกลับไปบอกก่อนลงมือ (ดู bugs.md 18 ส.ค.)

## 2026-09-04 — คำศัพท์ราคา · ช่องทางขาย (SRP Calculator)

42. **คำเรียกราคาในระบบ SRP ใช้ชุดนี้เท่านั้น** — `SRP แบรนด์` = ราคาป้ายที่แบรนด์ตั้งมา (MSRP) กรอกเป็น USD/EUR/SGD แล้วระบบแปลงเป็นบาท **ไม่เข้าสูตรต้นทุน ตัวคูณไม่มีผล** · `ราคาแนะนำ` = ต้นทุนรวม × ตัวคูณ ปัดเลขสวย · `ราคาขายจริง` = street price ที่ฟันธงขาย (Margin คิดจากช่องนี้) · เจ้าของเคยแจ้งว่า "คำนวณ SRP ผิด" ทั้งที่สูตรถูก — ผิดที่ชื่อคอลัมน์ทำให้เข้าใจว่า SRP คือผลของตัวคูณ
